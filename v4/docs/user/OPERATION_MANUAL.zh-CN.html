V4 复盘系统详细操作手册

本文面向日常使用，逐项说明 V4 主图、Calendar、Order Setup、Live Record、数据维护、换季、经济日历和 Tradovate 导入的操作方式。

适用页面：index.html 与 data-maintenance.html。当前主要品种为 NQ 和 ES。

1. 系统用途

V4 是图表式手工复盘系统，用于加载 NQ/ES K 线、回放行情、标注 PDA/Segment/SMT/Chart Note、记录 backtesting setup，并把真实或模拟成交复原为 Live Record。

边界：V4 不是自动交易系统，也不自动判断 setup 是否成立。Order Setup 和 Live Record 的复盘结论仍然由用户人工判断。

2. 启动与服务

项目用途操作
启动服务启动 API 与网页服务。bash v4/start.sh start
重启服务修改 API 代码或环境变量后使用。bash v4/start.sh restart
停止服务关闭 V4 服务。bash v4/start.sh stop
主页面图表复盘、标注、Order Setup、Live Record。http://127.0.0.1:8001/index.html
数据维护页面刷新 Databento、经济日历、VIX、换季、Tradovate 转换。http://127.0.0.1:8001/data-maintenance.html
API 健康检查确认后端是否运行。http://127.0.0.1:8766/v4/health

如果页面提示 Failed to fetch，先检查 API 是否在 8766 端口运行。

3. 主页面项目

顶部工具栏

项目用途使用说明
Date Range设置主图加载日期范围。输入或选择开始/结束日期。1M 大范围会使用窗口化显示，避免浏览器一次加载太多 K 线。
Compare打开或关闭 Comparison Window。用于 ES/NQ 对照、跨周期观察、SMT 与 progressive HTF replay。
Main主图品种。选择 NQ 或 ES。主图品种决定当前 workspace 的对象隔离。
Main TF主图周期。常用 1M、5M、1H、D。
Days显示/隐藏交易日分隔。日内复盘时建议打开。
Grid显示/隐藏网格。按视觉偏好使用。
Segments控制 segment 显示范围。可按 All 或其他过滤方式显示。
N窗口/加载参数。用于控制部分窗口化显示或定位相关数量，日常保持默认即可。
Archive打开导入/导出入口。用于导出当前 Main 的 Review JSON，或导入对应 Main 的复盘对象。
设置按钮显示偏好。调整显示模式、字体等图表展示选项。

Main Instrument 规则

  • 当前 Main 是 NQ 时，只显示和保存 NQ 的 PDA、Order Setup、Live Record 等对象。
  • 当前 Main 是 ES 时，只显示和保存 ES 的对象。
  • 导入 Review JSON 时，archive instrument 必须与当前 Main 一致，否则系统会拒绝导入。
  • Tradovate/MES 会映射到 ES，MNQ/NQ 会映射到 NQ。

4. 图表右键菜单

菜单项目用途操作方式
Locate定位当前 K 线或对象。用于快速回到对象所在时间。
Order Setup创建或操作 backtesting setup。选择 bullish/bearish setup，并继续设置 entry、stop、target、result。
Live Records创建或操作真实/模拟成交复盘对象。新建 bullish/bearish live record，设置 active record 的 entry、stop、target、exit，或关联证据。
PDA创建 PDA 标注。包括 BSL/SSL/FVG/IFVG/OB/Breaker/Wick CE/Fib 等。
SMT标注或定位 SMT 相关对象。主图与副图时间对齐后使用。
1M Segments绘制 1M price leg。从 high/low 起点开始，再选择终点。
Point Sets绘制 EQH/EQL 等点集。先 start，再 add point，最后 finish。
Chart Note添加图表备注。可作为 setup 或 live record 的证据引用。
Time Overlays显示时间线、killzone 等。用于日内时间段复盘。
Objective Gaps标注 objective gap。用于记录目标缺口或价格目标区。
Clear清理当前选择或对象。根据上下文清除选择、隐藏或删除对象。

5. Replay Bar

项目用途说明
Replay Bar On/Off打开/关闭回放。打开后只显示 replay cursor 之前的 K 线。
First跳到当前加载区间第一根。用于从头复盘。
Last Pos回到上次 replay 位置。适合中断后继续。
Pick从图上点选 replay 位置。只能选择已经显示出来的 K 线。
<后退一根或一个步长。用于细节复盘。
播放自动播放。再次点击可停止。
>前进一根或一个步长。用于逐根查看。
Next跳到下一个关键时间点。例如 09:29、09:30 等 replay 时间节点。
History恢复 replay workspace。恢复视图、cursor、Comparison Window 设置，不保存 K 线本身。

6. Calendar 与 Inspector

右侧 Inspector 是对象详情和每日复盘入口。Calendar 会按日期聚合当前 Main 的对象。

项目用途说明
Calendar 日期打开某一天的复盘对象列表。会显示 Order Setups、Live Records、Economic Events、PDA、Segments、SMT、Chart Notes 等。
Show Day Objects显示当天对象。将当天 PDA、Segments、Chart Notes 等显示到图表。
Hide Day Objects隐藏当天对象。用于清理视图。
Open打开对象详情。进入 Order Setup Detail、Live Record Detail 等详情面板。
Locate定位对象所在时间。图表会跳转到对象时间附近。
Back返回上一层面板。从 detail 回到 Calendar 日期页或上一面板。

7. Order Setup

Order Setup 用于 backtesting 或完美 setup 记录。图表上的 setup anchor 使用空心三角，与 Live Record 的实心三角区分。

详情项目用途使用说明
Header显示方向、时间、周期、品种、状态。双击 setup 三角会打开详情；同一时刻只应有一个 active setup。
Display / Risk Reward Box显示或隐藏风险收益框。用于视觉检查 entry、stop、target 的结构。
Summary记录 setup 总结。写主要判断，不需要写操作教程。
Anchor记录 reversal anchor。包括 reversal 类型、时间、TF、价格。
Execution显示 entry、stop、targets 等执行元素。如果没有设置，会显示 No execution elements。
Entry Context记录入场上下文。勾选 Purge + OB、OTE、Stop Market、Key Level、2022，选择 session。
Reasons记录 setup 理由。每条 reason 可选择类别、写 note，并链接 PDA/Segment/Chart Note 等对象。
Result记录结果。选择目标、失败、止损、最终结果，记录 exit time/price、points、R 等。

创建 Order Setup 流程

  1. 在目标 K 线右键，进入 Order Setup。
  2. 选择方向，例如 bullish 或 bearish setup。
  3. 双击图上的空心三角，打开 Order Setup Detail。
  4. 在图上右键设置 entry、stop loss、target、result。
  5. 在 Inspector 中填写 Summary、Entry Context、Reasons。
  6. 确认 Risk / Reward Box 是否正确显示。
  7. 复盘结束后填写 Result。

8. Live Record

Live Record 用于记录真实或模拟成交。它的 UI 尽量与 Order Setup 一致，但对象含义是“实际发生的交易”。图表上的 live anchor 使用实心三角。

项目用途说明
Create Bullish Live Record Here创建多头 live record。在当前 K 线价格创建 active live record。
Create Bearish Live Record Here创建空头 live record。在当前 K 线价格创建 active live record。
Set Active Live Record Anchor Here移动当前 active live record 的 anchor。只对 active live record 生效。
Set Entry Here设置成交 entry。用于标出真实入场价和时间。
Set MSS Here设置 market structure shift。可选，用于记录入场后结构确认。
Set Stop Loss Here设置止损。用于 risk box。
Targets设置目标。可设置 Target Internal 1/2/3、Swing Point、External 1/2/3。
Set Result / Exit Here设置最终 exit。用于结果面板与 exit 线。
Set All Ends Here设置所有元素结束时间。按住 Shift 打开右键菜单时可用，用于统一延长/截断 entry、stop、target 线。
Link PDA/Segment/Composite/SMT/Chart Note把当前上下文对象链接到 active live record。用于记录这笔 live trade 的证据。
Submitted标记订单已提交。生命周期状态。
Filled标记订单已成交。生命周期状态。
Cancel标记订单取消。生命周期状态。
Close标记交易关闭。关闭后不代表 reviewed。
Mark Reviewed标记复盘完成。通常在填写结果、原因、匹配 setup 后使用。
Clear Active Live Record取消当前 active live record。不删除对象，只取消 active 状态。

Live Record Detail 项目

详情项目用途说明
Header显示方向、时间、TF、品种和状态。双击 live 三角可打开详情并设为 active。
Lifecycle Buttons提交、成交、取消、关闭、review。根据当前状态显示允许的下一步。
Display控制 Risk / Reward Box。关闭后只隐藏 box，不删除元素。
Summary写这笔交易摘要。Tradovate 导入会自动填初始摘要。
Anchor记录 live anchor。显示方向、时间、TF、价格。
Matched Setup把 live trade 与当日 setup 匹配。下拉候选会优先显示同日同品种 setup，并带 entry/reversal 时间。
Execution显示 entry、stop、targets。可选择、隐藏、删除单个元素。
Entry Context记录实际入场上下文。与 Order Setup 的 entry context 保持一致。
Reasons记录交易理由。可追加 reason，并显示已链接证据对象。
Result记录结果。Exit type 可选 Profit / Stop Loss / Unknown；显示 hold、risk、points、R。

创建 Live Record 流程

  1. 在实际做单位置右键，进入 Live Records。
  2. 选择 Create Bullish Live Record Here 或 Create Bearish Live Record Here。
  3. 右键设置 Set Entry Here、Set Stop Loss Here、targets 和 exit。
  4. 双击实心三角，打开 Live Record Detail。
  5. 填写 Summary、Entry Context、Reasons。
  6. 在 Matched Setup 中选择同日 setup，或点 Match Active Setup。
  7. 检查 Result 面板的 exit type、points、R。
  8. 复盘完成后点击 Mark Reviewed。

9. Archive 导入导出

项目用途说明
Export Review JSON导出当前 Main 的复盘对象。包括 PDA、Segments、SMT、Order Setup、Live Record、Chart Notes 等。
Import Review JSON导入复盘对象。导入文件的 instrument 必须与当前 Main 一致。
Clear Saved Annotations清理本地保存对象。谨慎使用。会影响当前浏览器本地存储。
导入 ES archive 前，必须把顶部 Main 切到 ES。导入 NQ archive 前，必须把 Main 切到 NQ。

10. Data Maintenance 页面

地址：http://127.0.0.1:8001/data-maintenance.html。这个页面用于避免手写复杂命令。

Refresh Range

项目用途说明
Instrument选择刷新 ES 或 NQ。影响 Databento 拉取与 DB 写入品种。
Chunk days把请求拆成几天一段。常用 1 或 3。排查失败时用 1；补几天数据用 3。
Start optional手工指定起点。为空时从 DB 当前最新 bar 的下一分钟开始。
End required指定 exclusive end。2026-06-16T00:00:00 表示抓到这个时间之前。
Now把 End 填为当前美东时间。适合盘中手动刷新。
Session Close把 End 填为当天美东 17:00。适合收盘后补数据。
Preflight检查 roll segments 是否 write-eligible。跨换季边界写库前必须先跑。
Dry Run预览会下载和写入多少行。不写 DB。
Write confirmation写库保护确认框。ES 输入 WRITE ES，NQ 输入 WRITE NQ。
Write Data执行真实写库。只有 dry-run 合理后再点。

Economic Calendar

项目用途说明
From date经济日历开始日期。格式 YYYY-MM-DD。
To date经济日历结束日期。格式 YYYY-MM-DD。
Today设置为今天。From/To 都填今天美东日期。
This Week设置为本周。本周一到本周日。
Next Week设置为下周。下周一到下周日。
To Today从本地 CSV 最新日期补到今天。先跑 status，自动填 date_max + 1 到今天。
Status检查当前 CSV 状态。显示 rows、date_min、date_max、duplicate keys、malformed rows。
Dry Run预览新增事件。不写 CSV。
Verify校验本地 CSV 完整性。不联网、不写文件。
Write confirmation写入保护。必须输入 WRITE ECONOMIC。
Write Calendarappend-only 写入经济日历。会先备份 CSV，再追加新日期数据。

Roll Calendar

项目用途说明
Preset选择常用换季预设。当前包含 ES/NQ June 2026 预设，也可选 Custom。
Instrument换季品种。ES 或 NQ。
Roll date你确认实际切换的日期。必须与你交易系统实际切换一致。
Old contract旧合约。例如 ESM6、NQM6。
New contract新合约。例如 ESU6、NQU6。
Status换季确认状态。manual_validated 表示人工确认；volume_validated 表示成交量验证。
Note证据说明。写明为什么确认该 roll date。
Scan start/end成交量扫描区间。默认围绕 roll date 前后几天。
Scan Volume比较 old/new contract 成交量。输出 old/new 总量、first overtake、candidate roll date。
Use Candidate Date使用扫描候选日期。会把 candidate 填到 Roll date；字段变化后旧 candidate 会失效。
Roll Report查看需要注意的 roll entries。不会写文件。
Preview Confirm预览换季确认 diff。必须先看 diff。
Write Confirm写入 futures roll calendar。确认无误后再用。

Verification

项目用途说明
Verify Data检查 DB/VIX freshness。不调用 API smoke。
Verify Data + API检查数据和 API。适合写库后验证。
ES API Smoke单独测试 ES bars API。确认 ES 可读。
NQ API Smoke单独测试 NQ bars API。确认 NQ 可读。

Tradovate Live Records

项目用途说明
Performance CSV选择 Tradovate 导出的 Performance CSV。每一行会转换为一条 closed Live Record。
Instrument选择导出品种。Auto 会按 CSV 自动分 ES/NQ；混合 CSV 会生成多个 JSON。
Timestamp timezone解释 CSV 时间。当前常用 V4 chart wall time；如果 CSV 是真实时区时间，可选择 New York 或 Los Angeles。
Output filename输出 JSON 文件名。选择 CSV 后会按文件名、品种、日期范围自动生成。
Preview CSV预览转换结果。显示 rows、records、wins/losses、P/L。
Download Review JSON下载可导入 V4 的 Review JSON。导入前切换 Main 到对应 instrument。

11. 常用操作流程

流程 A：盘中手动刷新最新 1M 数据

  1. 打开 data-maintenance.html。
  2. 在 Refresh Range 选择 ES 或 NQ。
  3. 点击 Now，End 会填当前美东时间。
  4. 点击 Preflight，确认 write-eligible。
  5. 点击 Dry Run，检查 would insert rows。
  6. 确认无误后输入 WRITE ES 或 WRITE NQ。
  7. 点击 Write Data。
  8. 点击 Verify Data + API。

流程 B：更新今天经济日历

  1. 打开 Economic Calendar。
  2. 点击 To Today。
  3. 点击 Dry Run。
  4. 检查 would_append_rows。
  5. 输入 WRITE ECONOMIC。
  6. 点击 Write Calendar。
  7. 点击 Status 或 Verify。

流程 C：手动确认换季

  1. 选择 Roll Calendar preset 或 Custom。
  2. 确认 Instrument、Old contract、New contract。
  3. 设置 Scan start/end，点击 Scan Volume。
  4. 如认可 candidate，点击 Use Candidate Date。
  5. 在 Note 写明人工确认依据。
  6. 点击 Preview Confirm 看 diff。
  7. 确认只修改目标 entry 后，点击 Write Confirm。
  8. 回到 Refresh Range 跑 Preflight。

流程 D：导入 Tradovate 成交为 Live Record

  1. 打开 Data Maintenance 的 Tradovate Live Records。
  2. 选择 Performance CSV。
  3. Instrument 用 Auto 或指定 ES/NQ。
  4. 选择正确 Timestamp timezone。
  5. 点击 Preview CSV 检查结果。
  6. 点击 Download Review JSON。
  7. 回到主页面，切换 Main 到 JSON 对应品种。
  8. Archive 导入 JSON。
  9. 在 Calendar 当日 Live Records 中逐条打开复盘。

流程 E：把 Live Record 匹配到 Setup

  1. 打开当天 Calendar。
  2. 打开目标 Live Record Detail。
  3. 在 Matched Setup 下拉中选择同日 setup。
  4. 如果已经点亮目标 setup，可点 Match Active Setup。
  5. 确认 matched setup label 包含正确 entry/reversal 时间。
  6. 填写 Reasons 和 Result。
  7. 点击 Mark Reviewed。

流程 F：导出当天或当前区间复盘

  1. 确认顶部 Main 是目标品种。
  2. 确认 Date Range 覆盖要导出的对象。
  3. 点击 Archive。
  4. 点击 Export Review JSON。
  5. 文件名中应包含品种、时间等信息。
  6. 导入时必须先切换到同一 Main。

12. 排错

现象可能原因处理
页面 Failed to fetchAPI 未运行或端口不对。运行 bash v4/start.sh restart，再检查 /v4/health。
Databento dry-run 提示缺 keyAPI 进程环境缺少 DATABENTO_API_KEY。设置环境变量后重启 API。
Preflight blocked刷新范围跨过未确认 roll boundary。先在 Roll Calendar 确认换季，再重新 Preflight。
Economic dry-run 一直 running后端任务仍在跑或锁未释放。先点 Status；如果仍 busy，重启 API。
导入 JSON 失败 instrument mismatch当前 Main 与 archive instrument 不一致。切换 Main 到 JSON 对应品种后再导入。
Risk / Reward Box 不显示Display 关闭，或 entry/stop/target/exit 不完整。打开 Display，检查 execution 元素是否 complete。
Live 菜单操作不可用没有 active live record。双击 live 三角或在 hit menu 选择 Set Active。
Refresh Range 输出无新数据时间段在周末、数据源尚未更新、或 DB 已有数据。检查 dry-run range、databento_end_et、would_insert_rows。
写入前安全顺序：Roll 先 Preview 再 Write；数据刷新先 Preflight，再 Dry Run，再 Write；经济日历先 Dry Run，再 Write Calendar。
