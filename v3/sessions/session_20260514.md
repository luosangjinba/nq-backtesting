## 一、问题循环与根本原因

### 1.1 循环现象

在本次会话中，遇到了反复出现的问题：
1. 时间格式化不工作（`201201090200` 不格式化）
2. 加载数据无响应
3. 控制台语法错误
4. 修复后又出现新问题

**循环次数**：至少 3 次

### 1.2 根本原因分析

**技术层面**：
1. **代码插入方式不当**：使用 Python 字符串替换时，缩进不一致导致语法错误
2. **浏览器缓存顽固**：即使强制刷新，旧代码仍在运行
3. **`}` 配对问题**：sed 删除多行代码时误删配对括号（阶段 A 的历史问题）

**流程层面**：
1. **缺少验证步骤**：修改后没有立即测试，累积多个问题
2. **回退不彻底**：发现问题后回退到错误的版本
3. **修复方式激进**：用 sed/awk 等工具批量修改，风险高

### 1.3 解决方案

**立即措施**：
- 回退到最后一个已知可用版本（`6e17771`）
- 换端口启动服务（8001），避免缓存

**长期措施**：
- 每次修改后立即测试
- 使用更安全的代码插入方式（Edit 工具 > Python > sed）
- 阶段 D 后模块化拆分，降低单文件复杂度

## 四、技术要点

### 4.1 避免循环 bug 的方法

1. **小步提交**：每个功能点独立提交，便于回退
2. **立即验证**：修改后立即刷新浏览器测试
3. **换端口测试**：遇到缓存问题时换端口（8000 → 8001）
4. **保守修改**：优先用 Edit 工具，避免 sed/awk 批量操作

### 4.2 浏览器缓存处理

**问题**：即使 Ctrl+Shift+R 强制刷新，旧代码仍在运行

**解决方案**：
1. 关闭标签页，重新打开
2. 换端口启动服务（`python3 -m http.server 8001`）
3. 清空浏览器缓存（开发者工具 → Application → Clear storage）

### 4.3 代码插入的最佳实践

**优先级**：Edit 工具 > Python 文件读取 > Python 字符串 > sed/awk

**示例**：
```python
# 好：从文件读取，保持原始格式
with open('/tmp/popover_functions.txt', 'r') as f:
    code = f.read()
lines = lines[:insert_pos] + [code + '\n'] + lines[insert_pos:]

# 差：手写字符串，缩进易错
code = '''function foo() {
  console.log('bar');
}'''
```
