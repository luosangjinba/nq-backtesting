### 1. 时区显示问题修复（核心问题）

**问题现象：**
- BSL 标记显示在 12:00 而不是 07:00
- SSL 标记显示在 16:00 而不是 11:00
- 图表显示的是 UTC 时间，而不是美东时间

**根本原因：**
API 将数据库的美东时间转换成了 UTC timestamp，导致图表显示 UTC 时间。

**错误的解决思路（走了弯路）：**
1. 尝试用 Lightweight Charts 的 `timezone` 参数 → v4.1.3 不支持
2. 尝试升级到 v4.2.0 → API 不兼容，导致图表崩溃
3. 尝试升级到最新版 → 同样崩溃

**正确的解决方案：**
**不做时区转换！数据库时间当作 UTC 返回给前端！**

#### 修改内容

**API 修改**（`price_lookup_api.py` 第 1890 行）：
```python
# 修改前
et_tz = ZoneInfo("America/New_York")
"timestamp": int(row[0].replace(tzinfo=et_tz).timestamp())

# 修改后
utc_tz = ZoneInfo("UTC")
"timestamp": int(row[0].replace(tzinfo=utc_tz).timestamp())
```

**工作原理：**
```
数据库: 2012-01-09 07:00 (美东时间)
   ↓
API: 当作 UTC 处理 → timestamp 1326092400
   ↓
图表: 显示 UTC 时间 → 07:00 ✅
```

**测试标记 timestamp 更新：**
```javascript

addSslMarker(1326124800, ...)  // 显示 16:00

// 修改后（当作 UTC）
addBslMarker(1326092400, ...)  // 显示 07:00 ✅
addSslMarker(1326106800, ...)  // 显示 11:00 ✅
```

## 遇到的问题

### 问题 1: 时区混淆

**现象：** BSL 显示在 12:00 而不是 07:00

**根本原因：** 对时区转换的理解错误
- 以为需要 API 转换成 UTC，前端再用 `timezone` 参数转回来
- 实际上数据库本身就是美东时间，不需要转换

**教训：**
- 数据库时间 = 美东时间（naive datetime）
- API 应该"假装"这是 UTC 时间
- 图表显示 UTC 时间 = 实际显示美东时间

### 问题 2: Lightweight Charts 版本兼容性

**现象：** 升级版本后图表崩溃

**原因：**
- v4.1.3 不支持 `timezone` 参数
- v4.2.0+ API 可能有变化
- Custom Primitives API 在不同版本中可能不同

**教训：**
- 不要轻易升级库版本
- 升级前要查看 changelog 和 breaking changes
- 稳定版本优先于新功能

### 问题 3: Custom Primitives API 复杂性

**现象：** `draw()` 方法不被调用，或调用后崩溃

**原因：**
- Custom Primitives 需要实现特定接口
- `paneViews()` 不能直接返回 `this`
- 需要返回实现了 `renderer()` 等方法的对象

**教训：**
- Custom Primitives 比 Series Markers 复杂得多
- 需要仔细阅读官方文档和示例
- 先用简单的方式（Series Markers）实现，再考虑复杂的（Custom Primitives）

### 3. 修复价格轴 autoscale 跳动

**问题现象：**
- 刚加载页面时，在价格轴区滚动滚轮 → 除了 K 线横向缩放，价格轴也在动，不稳定
- 拖动鼠标左键缩放价格轴后 → 滚轮行为变稳定，只横向缩放图表

**根本原因：**

Lightweight Charts 的 autoscale 机制：

```javascript
// 默认状态（刚加载）
rightPriceScale: {
  autoScale: true,  // 价格范围自动适配可见 K 线
}
// 行为：滚轮缩放时间 → 可见 K 线变化 → 价格范围跟着变 → 价格轴"跳动"

// 拖动价格轴后（库自动改变）
rightPriceScale: {
  autoScale: false,  // 价格范围锁定
}
// 行为：滚轮只缩放时间，价格轴保持固定范围
```

**解决方案：**

在数据加载后立即锁定价格范围：

```javascript
// 设置数据
state.candlestickSeries.setData(candleData);

// 自动缩放到合适的视图
state.chart.timeScale().fitContent();

// 锁定价格范围，防止滚轮缩放时间轴时价格轴跟着跳动
state.chart.priceScale('right').applyOptions({ autoScale: false });
```

**效果：**
1. 首次加载数据 → `autoScale: true` 自动计算最佳价格范围
2. 立即锁定 → `autoScale: false` 防止后续跳动
3. 滚轮缩放时间轴 → 价格轴保持稳定
4. 手动拖动价格轴 → 可以调整价格范围

## 学习成果

### Lightweight Charts 机制

1. **DOM 结构：** 图表是 `<table>`，主图区/价格轴/时间轴是独立 canvas
2. **拖动区分：** `mousedown` 监听器挂在各自子元素上，通过 `event.target` 区分
3. **滚轮全局：** 只有一个 wheel handler，不区分区域，`handleScale.mouseWheel` 是全局开关
4. **autoScale 机制：**
   - `true`：价格范围自动适配可见 K 线
   - `false`：价格范围锁定
   - 拖动价格轴时库自动切换为 `false`

### 模块化策略

1. **渐进式拆分：** 先拆风险低的（CSS），再拆复杂的（JS）
2. **判断标准：** 单文件 < 800 行不拆，> 1200 行必须拆
3. **验证思路：** 每次拆分后验证功能，为下次积累经验

### 工具选择

1. **Edit vs sed：** 大块文本替换用 sed，精确小改用 Edit
2. **备份策略：** 改动前先 `cp` 备份，出问题可快速回退
3. **验证方式：** curl 测试可访问性 + 浏览器测试功能

**背景：**

- 不同于 BSL/SSL 的点标记，需要 Custom Primitives

**技术选型：**
- 方案 A：Price Lines（水平线）— 无法限定时间范围 ❌
- 方案 B：Custom Primitives（自定义图形）— 完全控制 ✅
- 方案 C：Series Markers + CSS hack — 不优雅 ❌

**决策：** 用 Custom Primitives，先做最简版本验证可行性

**实现步骤：**

1. **创建 FvgPrimitive 类**（~60 行）
   ```javascript
   class FvgPrimitive {
     constructor(centerTime, topPrice, bottomPrice, color = '#ab47bc') { ... }
     updateAllViews() { ... }  // Custom Primitives 必需方法
     draw(target) { ... }       // Canvas 绘制逻辑
   }
   ```
2. **坐标转换逻辑**
   - 时间戳 → `timeToCoordinate()` → 像素 x
   - 像素 x → `coordinateToLogical()` → 逻辑索引
   - 逻辑索引 ± 2 → `logicalToCoordinate()` → 矩形左右边界
   - 价格 → `priceToCoordinate()` → 像素 y

3. **Canvas 绘制**
   - 填充：`ctx.fillStyle = '#ab47bc33'`（紫色 + 20% 不透明度）
   - 边框：`ctx.strokeStyle = '#ab47bc'`（紫色实线，1px）

4. **辅助函数**
   - `addFvgMarker(centerTime, topPrice, bottomPrice)` — 添加 FVG
   - `clearFvgMarkers()` — 清空所有 FVG

5. **测试数据**
   - 时间：2012-01-09 02:00 ET（`1326074400`）
   - 顶部：2343.50
   - 底部：2342.00
   - 宽度：约 4 根 K 线（中心点 ± 2 逻辑单位）

**问题 1：矩形不显示**

**现象：** 控制台显示 "✓ 添加 FVG 标记"，但图表上看不到矩形

**排查过程：**

### Custom Primitives 工作原理

1. **接口要求：**
   - `updateAllViews()` — 通知图表重绘（必需）
   - `draw(target)` — Canvas 绘制逻辑（必需）

2. **坐标转换链：**
   ```
   时间戳 → timeToCoordinate() → 像素坐标
          → coordinateToLogical() → 逻辑索引
          → logicalToCoordinate() → 像素坐标
   
   价格 → priceToCoordinate() → 像素坐标
   ```

3. **挂载方式：**
   ```javascript
   const primitive = new FvgPrimitive(...);
   series.attachPrimitive(primitive);  // 挂载
   series.detachPrimitive(primitive);  // 卸载
   ```

4. **Canvas 绘制：**
   - `target.context` 提供 Canvas 2D 上下文
   - 用标准 Canvas API（`fillRect`, `strokeRect`）
   - 颜色支持 hex + alpha（如 `#ab47bc33`）

### 渐进式开发的价值

**对比：**
- ❌ 一开始就设计完整系统 → 改来改去定不下来 → 屎山
- ✅ 先做最简版本 → 验证可行性 → 用起来发现问题 → 迭代优化

**本次实践：**
- FVG 最简版本：固定颜色、固定时间范围、单个测试
- 验证通过后再扩展：批量加载、区分类型、动态范围

**查看源码：** `v2/scripts/scan_layer1_pda.py`
**FVG 检测逻辑：**
```python
# 三根 K 线：a, b, c
a = bars[i - 2]  # 第一根
b = bars[i - 1]  # 中间根（anchor_time）
c = bars[i]      # 第三根

# Bullish FVG: c.low > a.high
if c.low > a.high:
    price_high = c.low
    price_low = a.high
    anchor_time = b.bucket_start  # 中间那根 K 线的时间
```

**关键发现：**

**错误理解：**

#### Custom Primitives 正确实现

**三层架构：**
1. **Renderer**：Canvas 绘制，使用 `useBitmapCoordinateSpace`
2. **View**：坐标转换（时间/价格 → 像素）
3. **Primitive**：主类，`updateAllViews()` 调用 `view.update()`

**关键点：**
- 必须使用 `useBitmapCoordinateSpace` 处理高 DPI
- `paneViews()` 返回视图对象数组（不是 `this`）
- `horizontalPixelRatio` 和 `verticalPixelRatio` 要乘到坐标上
