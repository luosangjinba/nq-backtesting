### 1. 价格轴滚轮行为改进（失败 → 回退）

**问题：** 用户希望把"鼠标在价格轴上滚动滚轮"的行为改成与"在价格轴上按住左键拖动"一致（纵向缩放价格轴）。

**尝试方案：**
- 在 container 上 capture 阶段挂 wheel 监听器
- 通过 `mouseX` 与 `priceScale('right').width()` 判断是否落在价格轴区
- 拦截事件并用 `autoscaleInfoProvider` 自定义价格范围

**失败原因：**
- 引入自定义状态管理（`state.priceZoom.customRange`）
- 破坏了原生 pan 行为：缩放后无法拖动图表
- 改动规模超出"调参"范畴，进入自定义范围管理

**教训：**
- Lightweight Charts 的 `handleScale.mouseWheel` 是全局开关，无法区分"主图区"和"价格轴区"
- 库通过 DOM 子元素（独立 canvas）区分拖动区域，但滚轮只有一个全局 handler
- "调参即可"的边界：只通过官方参数影响行为，不引入自定义状态管理
- 非平凡功能要警惕"改动规模 vs 稳定性"——当需求开始覆盖库机制时，先评估是否属于库能力边界外

### 2. CSS 模块化重构

#### 2.1 规划阶段

**背景分析：**
- 当前 `kline_viewer.html` 507 行，其中 CSS 151 行（30%）
- HTML/CSS/JS 混在一起，修改样式需要翻到文件头部
- 未来加 PDA 工作台后会膨胀到 1500+ 行

**方案对比：**

| 方案 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| 单文件 | 零依赖、调试简单、部署简单 | 无法复用、扩展困难、测试困难 | 507 行还可维护 |
| JS 模块拆分 | 可复用、可测试、职责清晰 | 需要 ES6 module、调试稍复杂 | 推荐，渐进式 |
| iframe 嵌套 | 完全隔离 | 通信复杂、性能差、布局难 | 不推荐 |

**决策：渐进式模块化**
- Phase 1：先拆 CSS（风险最低，收益明显）
- Phase 2：观察代码增长，800+ 行再拆 JS
- Phase 3：按需拆分（PDA 工作台 → `pda-workbench.js`）

**判断标准：**
- < 800 行：不拆
- 800-1200 行：看复杂度
- \> 1200 行：必须拆

### 3. 修复价格轴 autoscale 跳动

**问题现象：**
- 刚加载页面时，在价格轴区滚动滚轮 → 除了 K 线横向缩放，价格轴也在动，不稳定
- 拖动鼠标左键缩放价格轴后 → 滚轮行为变稳定，只横向缩放图表

**根本原因：**

Lightweight Charts 的 autoscale 机制：

```javascript
// 默认状态（刚加载）
rightPriceScale: {
  autoScale: true,  // 价格范围自动适配可见 K 线
}
// 行为：滚轮缩放时间 → 可见 K 线变化 → 价格范围跟着变 → 价格轴"跳动"

// 拖动价格轴后（库自动改变）
rightPriceScale: {
  autoScale: false,  // 价格范围锁定
}
// 行为：滚轮只缩放时间，价格轴保持固定范围
```

**解决方案：**

在数据加载后立即锁定价格范围：

```javascript
// 设置数据
state.candlestickSeries.setData(candleData);

// 自动缩放到合适的视图
state.chart.timeScale().fitContent();

// 锁定价格范围，防止滚轮缩放时间轴时价格轴跟着跳动
state.chart.priceScale('right').applyOptions({ autoScale: false });
```

**效果：**
1. 首次加载数据 → `autoScale: true` 自动计算最佳价格范围
2. 立即锁定 → `autoScale: false` 防止后续跳动
3. 滚轮缩放时间轴 → 价格轴保持稳定
4. 手动拖动价格轴 → 可以调整价格范围

**现象：** `Edit` 工具对空格/tab 缩进非常敏感，old_string 稍有偏差就匹配失败

**现象：** 删除 `<style>` 块后，`</style>` 闭合标签残留

**解决：**
```bash
sed -i '/^  <\/style>$/d' v3/docs/kline_viewer.html
```

**教训：** 删除多行块时，检查闭合标签是否在删除范围内

## 学习成果

### Lightweight Charts 机制

1. **DOM 结构：** 图表是 `<table>`，主图区/价格轴/时间轴是独立 canvas
2. **拖动区分：** `mousedown` 监听器挂在各自子元素上，通过 `event.target` 区分
3. **滚轮全局：** 只有一个 wheel handler，不区分区域，`handleScale.mouseWheel` 是全局开关
4. **autoScale 机制：**
   - `true`：价格范围自动适配可见 K 线
   - `false`：价格范围锁定
   - 拖动价格轴时库自动切换为 `false`

### 模块化策略

1. **渐进式拆分：** 先拆风险低的（CSS），再拆复杂的（JS）
2. **判断标准：** 单文件 < 800 行不拆，> 1200 行必须拆
3. **验证思路：** 每次拆分后验证功能，为下次积累经验

### 工具选择

1. **Edit vs sed：** 大块文本替换用 sed，精确小改用 Edit
2. **备份策略：** 改动前先 `cp` 备份，出问题可快速回退
3. **验证方式：** curl 测试可访问性 + 浏览器测试功能
