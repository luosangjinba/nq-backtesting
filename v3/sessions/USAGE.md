# Sessions 使用指南

## 快速开始

### 1. 创建新会话

```bash
# 方式 1: 使用模板
cp v3/sessions/session_template.md v3/sessions/session_$(date +%Y%m%d).md

# 方式 2: 手动创建
vim v3/sessions/session_20260512.md
```

### 2. 编写会话记录

按照模板填写以下内容：
- 会话信息（日期、时长、目标）
- 完成的工作
- 技术决策
- 遇到的问题
- 代码变更
- 下一步计划

### 3. 更新索引

编辑 `v3/sessions/README.md`，在会话索引表中添加新记录：

```markdown
| 2026-05-12 | [session_20260512.md](session_20260512.md) | 实现 FVG 标记 | 🔄 进行中 |
```

## 会话记录规范

### 必填项

- ✅ 会话信息（日期、时长、目标）
- ✅ 完成的工作（至少一项）
- ✅ 代码变更（如有）
- ✅ 会话总结

### 选填项

- 技术决策（重要决策时填写）
- 遇到的问题（有问题时填写）
- 性能数据（性能相关时填写）
- 测试结果（测试相关时填写）

## 技术决策记录

### 何时记录

- 选择技术方案时
- 改变架构设计时
- 引入新依赖时
- 修改核心逻辑时

### 记录格式

```markdown
### 决策 X: 标题

**问题：** 需要解决什么问题

**方案：** 选择的方案

**原因：**
- 原因 1
- 原因 2

**替代方案：**
- 方案 A - 为什么不选
```

## 问题记录

### 何时记录

- 遇到 bug 时
- 遇到性能问题时
- 遇到设计问题时
- 遇到配置问题时

### 记录格式

```markdown
### 问题 X: 标题

**现象：** 详细描述

**原因：** 根本原因

**解决：** 解决方法

**教训：** 经验总结
```

## 代码变更记录

### 记录内容

- 新增文件（路径、行数、说明）
- 修改文件（路径、修改内容）
- 删除文件（路径、原因）

### 示例

```markdown
### 新增文件
- `v3/modules/fvg_module.js` (250 行) - FVG 标记模块

### 修改文件
- `v3/docs/kline_viewer.html` - 集成 FVG 模块
  - 引入 fvg_module.js
  - 添加 FVG 绘制逻辑
```

## 会话状态

| 状态 | 图标 | 说明 |
|------|------|------|
| 完成 | ✅ | 会话已完成，所有目标达成 |
| 进行中 | 🔄 | 会话正在进行 |
| 暂停 | ⏸️ | 会话暂停，等待外部条件 |
| 取消 | ❌ | 会话取消，目标改变 |

## 查看历史会话

### 按日期查看

```bash
# 查看特定日期的会话
cat v3/sessions/session_20260511.md

# 查看最近的会话
ls -lt v3/sessions/session_*.md | head -5
```

### 搜索关键词

```bash
# 搜索包含特定关键词的会话
grep -r "Lightweight Charts" v3/sessions/

# 搜索特定问题
grep -r "问题.*加载按钮" v3/sessions/
```

## 会话统计

### 统计代码量

```bash
# 统计所有会话的代码变更
grep -h "代码量" v3/sessions/session_*.md
```

### 统计文件数

```bash
# 统计新增文件数
grep -h "新增文件" v3/sessions/session_*.md | wc -l
```

## 最佳实践

### 1. 及时记录

- ✅ 每次开发会话结束后立即记录
- ✅ 重要决策当场记录
- ✅ 问题解决后立即记录

### 2. 详细描述

- ✅ 问题描述要详细，包含现象和原因
- ✅ 解决方案要具体，包含步骤
- ✅ 代码变更要清晰，包含说明

### 3. 保持一致

- ✅ 使用统一的文件命名
- ✅ 使用统一的格式
- ✅ 使用统一的术语

### 4. 定期回顾

- ✅ 每周回顾一次会话记录
- ✅ 总结常见问题和解决方案
- ✅ 提炼最佳实践
