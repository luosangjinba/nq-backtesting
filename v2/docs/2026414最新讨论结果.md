  - 用标准 FVG 定义（三根K线中间实体不接触）
  - 输出：每个 timeframe 的所有 FVG（日期、价格边界、方向）

步骤3：扫 VI
  - 扫描相邻两根K线之间的价格缺口
  - 输出：所有 VI（日期、价格边界、方向）

步骤4：扫 NWOG / NDOG
  - NWOG：周五16:59 → 周一18:00的缺口
  - NDOG：当日16:59 → 次日18:00的缺口
  - 输出：所有 NWOG / NDOG（日期、价格边界、方向）

步骤5：扫 BSL / SSL 候选点
  - 用候选规则识别高点上方/低点下方
  - 不做任何过滤（不判断是否被扫过）
  - 输出：所有候选 BSL / SSL（日期、价格）

步骤6：整合存档
  - 按 instrument + timeframe + date 组织
  - 存为 DuckDB 表 + 可导出 YAML
  - 方便第二层按日期范围快速查询


第二层：Structure Path

核心目标：给定日期范围，逐段建立结构路径记录，判断反转性质。

步骤1：确定 dealing range（锚定用）
  - 手工选择：哪两个 swing 构成当前 dealing range
  - 程序自动算：equilibrium、position_pct、premium_discount
  - 程序自动标注：range high 以上 = 外部流动性，range low 以下 = 外部流动性

步骤2：建立 swing 序列（以1H为例）
  - 从 dealing range 的锚定起点开始
  - 逐个连接相邻的 swing_high / swing_low
  - 形成序列：[swing_low_A → swing_high_A → swing_low_B → swing_high_B → ...]
  - 程序自动标注每段的：起止时间、起止价格、跨越点数

步骤3：人工判断每段 swing 的性质
  - HH：高于前一个 swing_high
  - HL：高于前一个 swing_low
  - LH：低于前一个 swing_high
  - LL：低于前一个 swing_low
  - 这是形成结构的 swing，还是只是填补不平衡的小回调

步骤4：判断反转原因
  - 如果是结构反转（HH/HL/LH/LL）：
    - 反转时的 HTF PDA 是什么（FVG / BSL / SSL / OB）
    - 反转时与前一个 swing 的关系是什么
    - 目的地是哪里（internal / external）
  - 如果是不平衡填补（非结构反转）：
    - 是哪种不平衡（FVG / VI / NWOG / NDOG）
    - 回调幅度有多大
    - 是否制造了可交易的 LTF 机会

    步骤5：记录路径类型
  - internal_to_external：内部低点 → 外部高点
  - external_to_internal：外部高点 → 内部低点
  - internal_to_internal：内部回调
  - external_to_external：突破后继续往外部走
  - imbalance_rejection：因不平衡填补产生的小型反转

步骤6：归因记录
  - 记录当时的 HTF 结构背景
  - 记录价格行为细节
  - 记录最终结果（到达 / 未到达 / 部分到达）

Phase 1（先做）：第一层数据库
  1. 建 DuckDB schema（pda_registry + pda_events）

  3. 写 FVG / VI 扫描器
