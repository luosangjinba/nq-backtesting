# Project Profile

更新时间：2026-04-09

## 项目定义

这是一个 `历史复盘 / backtesting` 系统，不是完整的 `trading journal`。

它的核心目标不是记录交易生活全貌，而是通过结构化数据，研究：

- `9:30` 之后 `1 小时` 的走势概率
- `9:30-10:30` 之间各类机会出现的概率
- 哪些盘前条件、开盘后事件、执行方式更有 edge

一句话定义：

> 这是一个以 `9:29` 为固定观察截面、以 `9:30-10:30` 为主要研究窗口、以结构化盘前背景和开盘后机会记录为核心的数据型 backtesting 系统。

## 时间边界

- 盘前判断统一截面：`9:29`
- 主要研究窗口：`9:30-10:30`
- 系统默认服务于“伪实盘式复盘”
  - 也就是站在 `9:29` 时点，只使用当时可见的信息做判断

## 一级原则：时间优先

在这套系统里，`时间` 是一级核心变量，优先级高于价格。

这意味着：

- 关键点首先是“什么时间发生”，其次才是“发生在什么价格”
- bias、session、reversal、entry、target 的研究，优先围绕时间窗口展开
- 同样的价格行为，发生在不同时间段，含义可能完全不同
- 价格是重要信息，但要服从时间结构

后续写程序时应默认遵守：

- 如果一个字段能表达时间结构，就不要只记录价格结果
- 如果一个逻辑脱离时间窗口，只谈价格高低，优先级应降低
- 所有自动推算都要优先考虑“这个行为发生在几点、属于哪个时间窗口”

## 系统关注的三层信息

### 1. 盘前输入

指 `9:29` 之前已经可知的信息，包括：

- HTF Context
- Session Bias
- 隔夜关键点
- EQH / EQL
- FVG / OB / NWOG / NDOG
- ORR
- 盘前行情段

### 2. 开盘后事件

指 `9:30-10:30` 之间发生的行为，包括：

- reversal
- sweep
- tap
- fill
- break
- looming
- 盘中 EQH / EQL
- 盘中 FVG / OB

### 3. 机会结果

指机会是否真的可交易，以及最终表现如何，包括：

- tradeable / skip_reason
- entry model / entry style
- internal_reached
- swing_reached
- outcome
- swing review

## 非目标

为了避免系统跑偏，以下内容不是当前阶段重点：

- 完整情绪日记
- 全天交易流水
- 自动交易执行
- 与 `9:30-10:30` 概率研究无关的宏观分析

## 字段设计原则

以后增加字段时，优先问 4 个问题：

1. 这个字段是否帮助研究 `9:30-10:30` 的走势概率？
2. 这个字段是否帮助研究 `9:30-10:30` 的机会概率？
3. 这个字段是否能在 `9:29` 时点被合理定义？
4. 这个字段是否强调了时间结构，而不只是价格结果？

如果以上大多不能回答“是”，就不应优先加入系统。

## 自动化原则

- 自动化用于辅助计算，不替代关键主观判断
- 自动化优先做客观字段：
  - 时间映射
  - 价格查询
  - 区间定位
  - premium / discount
  - 自动方向
- 对主观性强的字段保持保守：
  - bias
  - narrative
  - nearest draw
  - skip reason

## 样本原则

这个系统的最终目的是“堆样本”，不是“即时证明某套理论正确”。

因此：

- 优先记录客观结果
- 少做事后美化
- 尽量保持字段标准化
- 能用统一研究基准时，就不要混用多个标准

## 当前开发优先级

### 推荐优先

1. 继续扩展 HTF Context
2. 完善 swing 研究字段
3. 强化时间相关的事件结构记录

### 可以后做

1. bias updates
2. sweep / break 量化研究层
3. 更重的 target 结构重构

### 暂不建议做

1. 完整 journal 化扩展
2. 主题系统
3. 与研究目标弱相关的装饰性功能

## 后续使用方式

以后每当要增加功能时，先用这份文件做一次判断：

- 这个新增功能，是不是更接近 `backtesting`，而不是 `full journal`
- 它是不是服务于 `9:29 -> 9:30-10:30`
- 它是不是强化了“时间优先”
- 它是不是能帮助形成更干净的概率样本

如果答案是否定的，就应该谨慎推进。
