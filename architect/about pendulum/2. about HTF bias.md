## 可量化的部分：Dealing Range + Premium/Discount

一旦你定义了一个 dealing range（一个显著的 swing high 和一个显著的 swing low），后面全部是算术。equilibrium 就是 (high + low) / 2，价格在 equilibrium 之上就是 premium，之下就是 discount。你甚至可以算出当前价格在这个 range 里的百分位，比如 72% 就是明确的 premium。

ICT 的核心逻辑是：价格在 premium 倾向向下扩展，在 discount 倾向向上扩展。这一步完全可量化，没有任何主观成分。

## 半量化的部分：选择哪个 Dealing Range

真正的主观判断藏在前一步——你选哪个 swing high 和 swing low 来构成 dealing range。是用日线最近一个 swing？还是周线级别的 swing？还是月线级别？不同人画的 dealing range 不一样，结论就可能不一样。

但这个也不是完全不能结构化。你可以要求自己每次都记录：

- dealing range 的 swing high 价格和时间
- dealing range 的 swing low 价格和时间
- 你看的是什么周期（daily / weekly / monthly）

只要你把这三个值记下来，"当前价格在 premium 还是 discount"就变成了一个确定性的计算。不同人的分歧只是在 dealing range 的选择上，而你的选择一旦记录下来，后续可以回测验证你选的 range 预测力如何。

## 可量化的部分：Draw on Liquidity

Draw on liquidity 也是半量化的。你可以记录：

- 当前价格上方最近的未被触碰的 swing high / equal highs 价格
- 当前价格下方最近的未被触碰的 swing low / equal lows 价格
- 上方或下方是否有未回填的 daily/weekly FVG

这些都是你在图上可以客观标注的价位。"draw on liquidity 在上方"意味着你认为价格更可能先向上方的流动性池扩展。

## 可量化的部分：Daily Candle 结构

最近 1-3 根日线的方向、收盘位置也可以作为输入。比如：

- 前一根日线是阳线还是阴线
- 前一根日线收在自身 range 的什么位置（上 1/3、中 1/3、下 1/3）
- 最近三根日线是否形成了一个方向一致的序列

这些你的数据库已经能算。

## 核心原则：原始记录是"快照"，不能改

你在开盘前记录的 HTF context 代表的是你**当时的认知**。如果事后修改，你就失去了回测的基础——你永远不知道自己当初的判断到底对不对。

正确的做法是两步：

**第一步：在记录 bias 时，同时定义失效条件**

**第二步：当失效条件触发时，新增一条 bias update，而不是覆盖原记录**

## 具体结构

在原有的 `htf_context` 里新增两个字段：

```yaml
htf_context:
  # ====== 原有字段不变 ======
  dealing_range: { ... }
  position_pct: 68.7
  premium_discount: premium
  liquidity_above: [...]
  liquidity_below: [...]
  nearest_draw: above
  nearest_draw_target: 2398.5
  bias: bearish
  bias_confidence: medium
  narrative: sweep_then_reverse
  reasoning: "..."

  # ====== 新增：失效条件（开盘前定义）======
  invalidation:
    - condition: "日线收盘价 > 2398.5"
      implication: "dealing range 被突破，bearish bias 失效"
    - condition: "扫完2398.5后无15分钟级别bearish MSS"
      implication: "sweep_then_reverse叙事失效，可能转bullish"

  # ====== 新增：Bias 修正日志 ======
  bias_updates: []
```

`invalidation` 是你**在交易日开始前**就写好的。这一步非常重要，因为它迫使你提前想清楚"什么情况下我是错的"。

## Dealing Range 失效的判断标准

这个也可以半量化：

| 失效信号                             | 量化程度 | 说明                                         |
| ------------------------------------ | -------- | -------------------------------------------- |
| 日线收盘 > swing high                | 完全量化 | 最强的失效信号                               |
| 日线收盘 < swing low                 | 完全量化 | 向下突破                                     |
| 价格突破 swing high 但日线未收在上方 | 半量化   | 可能是 sweep，需要看后续反应                 |
| 扫完 liquidity 后无 LTF 反转结构     | 半量化   | 你需要定义"多长时间内"和"什么级别的反转结构" |

这里引出一个关键区分：**sweep vs. break**。

- **Sweep**：价格快速刺穿一个 liquidity level 然后回来，通常在较低时间框架上留下一个长影线。
- **Break**：价格突破后站稳，收盘在上方。

你可以在 `invalidation` 里明确写："如果是 sweep（影线刺穿但收回），bias 不变；如果是 break（收盘在上方），bias 失效。"这就把一个模糊的判断变成了一个相对客观的标准。

## 回测价值

有了这个结构后，你可以统计：

1. **invalidation 准确率**：你预定义的失效条件触发时，原始 bias 确实是错的比例是多少？如果很高，说明你的失效条件设得好。
2. **bias_update 的质量**：你修正 bias 之后，新的 bias 正确率是多少？是变好了还是变差了？（有些人越改越错，因为被盘中情绪带走了。）
3. **narrative 准确率**：你标注 `sweep_then_reverse` 的情况中，真正反转的比例是多少？如果低于50%，也许你需要重新审视这个叙事的使用场景。
4. **不改 bias 的收益 vs. 改了 bias 的收益**：这是最终极的检验——你的 bias update 到底在帮你还是在害你。

这最后一点尤其重要。很多交易者的问题不是不会修正 bias，而是修正得太频繁、太快，被市场的每一个波动带着走。数据会告诉你真相。

这个问题非常好，因为 sweep vs. break 的判断直接决定了你的 bias 是否需要修正。如果你把 sweep 误判为 break，你会过早翻转 bias；反过来，你会在趋势已经改变时还死守原来的方向。

## 核心原则：日线收盘是第一判据

ICT 框架里反复强调的一点是：**影线是骗人的，收盘价才是真相。** 价格在盘中刺穿一个关键水平但收盘拉回来，和价格收盘站在水平另一侧，这是两个完全不同的事件。

所以第一层判断完全可量化：

```
价格触及关键水平后，该根日线收盘在哪一侧？
```

这一步没有任何主观成分。

## 决策树

把 sweep vs. break 的判断拆成一棵决策树，每一步都是客观可验证的：

```
Step 1: 日线收盘是否在水平的另一侧？
│
├── 否（收盘拉回来了）
│   └── → SWEEP（高置信度）
│         影线刺穿但body回到原侧
│
└── 是（收盘站在另一侧）
    │
    Step 2: 第二根日线是否也收在另一侧？
    │
    ├── 否（第二天收回来了）
    │   └── → AMBIGUOUS
    │         一天的收盘可能是假突破
    │         保持原bias但降低confidence
    │
    └── 是（连续两天收在另一侧）
        └── → BREAK（高置信度）
              dealing range 失效，需要重新定义
```

这棵树只用了两个输入：第一根日线收盘位置、第二根日线收盘位置。完全客观，零主观判断。

但你可能会说：等两根日线太慢了，盘中就要做决策。所以需要第二层标准。

## 盘中快速判断：LTF 确认层

当价格触及 HTF 关键水平后，你可以在低时间框架上观察反应。这一层是半量化的，但可以通过结构化记录把主观成分压到最低：

```
价格触及 HTF 水平后，切换到 15 分钟图：

情况A：30分钟内出现反方向的 MSS
  → 支持 SWEEP 判断
  → 可以在日线收盘前就按 sweep 操作

情况B：出现同方向的 displacement candles（连续大实体小影线）
  → 支持 BREAK 判断
  → 不等日线收盘，直接视为 break

情况C：价格在水平附近横盘震荡，无明确结构
  → AMBIGUOUS
  → 等日线收盘再判断
```

"30分钟内"和"MSS"都是可以客观识别的，displacement candle 也可以量化定义（下面会讲）。

## 量化辅助指标：用 ATR 标准化

不同品种、不同波动率环境下，"刺穿了多远"这个距离的意义完全不同。黄金刺穿 5 个点和 BTC 刺穿 500 个点可能是同样的程度。用 ATR 标准化可以让你的标准跨品种、跨时期一致。

定义几个可计算的指标：

```yaml
# 价格触及水平后的量化测量
level_interaction:
  level: 2398.5
  level_type: swing_high
  
  # 1. 穿透深度（完全量化）
  max_penetration: 12.5          # 价格超过水平的最大距离（点）
  daily_atr_14: 85.0             # 14日ATR
  penetration_atr_pct: 14.7      # 穿透深度 / ATR × 100
  
  # 2. 日线body位置（完全量化）
  candle_close: 2391.0           # 该日线收盘价
  close_vs_level: below          # above / below / at
  body_beyond_pct: 0             # 日线body在水平另一侧的比例(%)
  
  # 3. Wick ratio（完全量化）
  upper_wick: 12.5               # 上影线长度
  candle_range: 45.0             # 日线总range (high-low)
  wick_ratio: 27.8               # 上影线 / 总range × 100
```

基于这些指标，可以建立经验阈值：

| 指标                  | Sweep 特征      | Break 特征              |
| --------------------- | --------------- | ----------------------- |
| `penetration_atr_pct` | < 30%           | > 50%                   |
| `close_vs_level`      | 回到原侧        | 站在另一侧              |
| `body_beyond_pct`     | 0%              | > 50%                   |
| `wick_ratio`          | > 25%（长影线） | < 10%（短影线或无影线） |

**这些阈值不是固定真理**，但它们给你一个起点。积累数据后你可以回测："当 `penetration_atr_pct < 30%` 且 `close_vs_level = below` 时，后续价格反转的概率是多少？"然后调整阈值。

## Displacement Candle 的量化定义

前面提到 LTF 的 displacement candles 也可以量化。一个简单的定义：

```
一根 displacement candle 满足以下全部条件：
1. body 占总 range 的比例 > 70%（实体大、影线小）
2. range > 1.5 × 该时间框架最近20根K线的平均range
3. 收盘在 range 的极端 25% 区域内
```

连续出现 2-3 根这样的 candle 朝同一方向，就是 displacement。这三个条件全部可计算。

## 综合打分

把上面所有指标组合成一个结构化的打分：

```yaml
sweep_break_assessment:
  # === 日线层面（权重最高）===
  daily_close_side: same         # same = 收回原侧, opposite = 站在另一侧
  daily_close_score: -2          # same = -2, at_level = 0, opposite = +2
  
  next_daily_close_side: null    # 第二天还没收盘时为null
  next_daily_score: null         # same = -2, opposite = +2
  
  # === 穿透深度 ===
  penetration_atr_pct: 14.7
  penetration_score: -1          # <30% = -1, 30-50% = 0, >50% = +1
  
  # === Wick ratio ===
  wick_ratio: 27.8
  wick_score: -1                 # >25% = -1, 10-25% = 0, <10% = +1
  
  # === LTF 结构（15分钟）===
  ltf_mss_against: true          # 是否出现反方向MSS
  ltf_displacement_through: false # 是否出现同方向displacement
  ltf_score: -2                  # MSS against = -2, displacement = +2, neither = 0
  
  # === 综合 ===
  total_score: -6                # 范围大约 -9 到 +9
  classification: sweep          # 规则见下
  classification_confidence: high
```

分类规则：

```
total_score <= -3  →  SWEEP（置信度随绝对值增大而增高）
total_score >= +3  →  BREAK
-3 < total_score < +3  →  AMBIGUOUS
```

在你的场景里——日线收回原侧（-2）、穿透浅（-1）、长上影线（-1）、15分钟出现反向 MSS（-2）——总分 -6，明确是 SWEEP。

## 一、三个核心决策的回答

在展开完整方案之前，先直接回答你提出的三个问题。

**判断时间节点：美东 8:00–9:15 完成分析，9:30 锁定 bias。** 9:30 是纽约现货开盘，ICT 框架中 killzone 的起点。你需要在开盘前完成所有 HTF 分析，9:30 之后你的工作是执行而不是分析。选 9:30 作为"锁定"时刻而非"分析"时刻，是因为分析需要时间，而你不应该在 killzone 已经开始后还在犹豫方向。

**Dealing Range 周期：日线（1D）。** 理由是 dealing range 代表的是"大资金的操作区间"，这个区间必须在机构级别的时间框架上才有意义。4H 的 swing 太频繁，一周内可能形成 3-4 个 4H dealing range，它们之间互相嵌套，反而让你无所适从。日线 dealing range 一个月可能只有 1-2 个，足够稳定，也足够清晰。4H 不是不用，而是降级为"确认层"——当日线 bias 确定后，4H 用来确认日内方向和寻找入场时机。

**Liquidity 周期：日线为主，4H 为辅。** 日线级别的 equal highs、equal lows、明显的 swing high/low 是机构真正关注的 liquidity pool，这些是你判断"价格要去哪"的锚点。4H 的 liquidity 用于细化目标——当你知道日线 liquidity 在 2398.5 时，4H 可能告诉你在 2395 和 2398.5 之间还有一个 4H 的 equal high 在 2396，这可以帮你优化入场和止损，但不改变你的方向判断。

## 二、时间流程

每个交易日的 HTF bias 工作分三个阶段。

第一阶段是**盘前分析**（美东 8:00–9:15）。这个阶段你做三件事：更新日线图上的 dealing range、标注日线和 4H 的 liquidity levels、根据价格在 dealing range 中的位置确定 bias。所有判断在这个阶段完成，记录进当天的 YAML 文件。

第二阶段是**盘中执行与监控**（美东 9:30–12:00，即 NY AM killzone）。这个阶段你只做两件事：按 bias 方向在 LTF 上找入场机会，以及监控 invalidation 条件是否被触发。如果触发了，写 bias_update，调整或停止操作。

第三阶段是**盘后复盘**（收盘后任意时间）。记录当天日线收盘价，更新 sweep/break 分类，评估 bias 是否需要为第二天调整。

## 三、Dealing Range 定义规则

Dealing Range 是日线图上**最近一段完整价格扩展的高低点**。"完整"的意思是：价格从一个方向运动到另一个方向，形成了一个可识别的 swing high 和 swing low。

识别方法如下。在日线图上找到最近的一个 swing high 和一个 swing low，要求 swing high 左右各至少有 3 根日线的高点低于它，swing low 左右各至少有 3 根日线的低点高于它。这两个点围成的区间就是你的 dealing range。

```yaml
dealing_range:
  # === 识别规则 ===
  timeframe: 1D
  swing_confirmation_bars: 3     # 左右各需要3根K线确认
  
  # === 当前值 ===
  swing_high: 2398.5
  swing_high_date: "2012-01-03"
  swing_low: 2310.0
  swing_low_date: "2011-12-28"
  range_size: 88.5               # swing_high - swing_low
  equilibrium: 2354.25           # (swing_high + swing_low) / 2
  
  # === Premium / Discount 分区 ===
  premium_zone:                  # 上半区（卖方区域）
    upper: 2398.5
    lower: 2354.25
  discount_zone:                 # 下半区（买方区域）
    upper: 2354.25
    lower: 2310.0
```

Dealing range 的更新条件只有一个：**日线收盘价突破了当前 dealing range 的 swing high 或 swing low**。影线刺穿不算突破。一旦突破发生，旧的 dealing range 作废，你需要等新的 swing 结构形成后重新定义。在"等待期"内，bias 标记为 `neutral`，不做方向性交易。

## 四、Liquidity 标注规则

Liquidity 分两层标注。

**日线层（决定方向）** 标注以下三类：第一类是 equal highs / equal lows，即日线图上两根或以上 K 线的高点（或低点）落在极小的价格区间内（差值 < 0.15 × ATR14），形成一条明显的"平顶"或"平底"。第二类是 prominent swing high / swing low，即不构成 equal highs/lows 但孤立突出的日线 swing point。第三类是前一周的高低点（weekly high/low），这在每周一的分析中标注。

**4H 层（细化目标）** 标注逻辑相同，但只标注位于日线 liquidity 附近的 4H 级别 liquidity。"附近"的定义是日线 liquidity level ± 1.0 × 4H ATR14 范围内。不在这个范围内的 4H liquidity 不标注，避免信息过载。

```yaml
liquidity:
  # === 日线级别（方向决策用）===
  daily:
    above_current_price:
      - level: 2398.5
        type: swing_high
        formation_date: "2012-01-03"
        touch_count: 1
        priority: primary          # primary = 最近且最明显的
      - level: 2425.0
        type: equal_highs
        formation_date: "2011-12-20"
        touch_count: 2
        priority: secondary
    below_current_price:
      - level: 2310.0
        type: swing_low
        formation_date: "2011-12-28"
        touch_count: 1
        priority: primary
        
  # === 4H 级别（入场细化用）===
  four_hour:
    near_daily_levels:
      - level: 2396.0
        type: equal_highs
        parent_daily_level: 2398.5   # 关联到哪个日线level
        distance_to_parent: 2.5
```

标注的核心原则是**只标注最近、最明显的 1-2 个**方向上的 liquidity。不要把图上每一个 swing point 都标出来。你的目标是识别"价格最可能被吸引到的下一个位置"，而不是画一张密密麻麻的线图。

## 五、Bias 判断规则

Bias 的确定基于两个输入：价格在 dealing range 中的位置、以及 liquidity 的分布方向。

**Position（位置）** 的计算方式：

$\text{position\_pct} = \frac{\text{current\_price} - \text{swing\_low}}{\text{swing\_high} - \text{swing\_low}} \times 100$

当 position_pct > 50 时，价格在 premium zone；< 50 时在 discount zone。

**Bias 判定的决策矩阵：**

| 价格位置                   | 最近的未被触及的 liquidity 方向 | Bias            | Confidence            |
| -------------------------- | ------------------------------- | --------------- | --------------------- |
| Premium（> 70%）           | 上方有日线 liquidity 未被扫     | bearish         | medium — 等扫完再做空 |
| Premium（> 70%）           | 上方 liquidity 已被扫           | bearish         | high — 可以找空头入场 |
| Premium（50-70%）          | 上方有 liquidity                | neutral-bearish | low — 方向不明确      |
| Discount（< 30%）          | 下方有日线 liquidity 未被扫     | bullish         | medium                |
| Discount（< 30%）          | 下方 liquidity 已被扫           | bullish         | high                  |
| Discount（30-50%）         | 下方有 liquidity                | neutral-bullish | low                   |
| Equilibrium 附近（40-60%） | 任意                            | neutral         | — 不做方向性交易      |

这个矩阵的核心逻辑是：价格在 premium zone 倾向于下跌（做空），在 discount zone 倾向于上涨（做多），在 equilibrium 附近不做判断。Liquidity 的存在会在 bias 确定后进一步影响 confidence 和交易时机。

**Narrative（叙事）** 是对 bias 的进一步解释，它描述你预期价格将如何到达目标。常见的 narrative 有以下几种：

```yaml
narrative_types:
  sweep_then_reverse:   "价格先扫完一侧liquidity，然后反转向另一侧"
  direct_expansion:     "价格从当前位置直接向bias方向扩展"
  range_to_range:       "价格从当前dealing range的一端走向另一端"
  continuation:         "价格已经在bias方向上运动，预期继续"
```

Narrative 不改变你的方向判断，但影响你的入场策略。比如 `sweep_then_reverse` 意味着你不会在价格还没扫完上方 liquidity 时就做空，你会等它扫完再入场。

## 六、Invalidation 与 Bias Update

每次记录 bias 时，同时写下失效条件。失效条件必须是客观可验证的，格式如下：

```yaml
invalidation:
  primary:                         # 主要失效条件（触发则直接修改bias）
    condition: "日线收盘 > 2398.5"
    action: "bearish bias 失效，写 bias_update 改为 neutral"
  secondary:                       # 次要失效条件（触发则降低confidence）
    condition: "价格触及2398.5后30分钟内无15分钟bearish MSS"
    action: "narrative从sweep_then_reverse降级为ambiguous，confidence降为low"
```

当 invalidation 触发时，操作流程是：不修改原始记录，而是追加一条 bias_update：

```yaml
bias_updates:
  - timestamp: "2012-01-05T15:30:00"
    trigger: "primary invalidation triggered - 日线收盘2402.3 > 2398.5"
    old_bias: bearish
    old_confidence: medium
    new_bias: neutral
    new_confidence: null
    action_taken: "停止寻找空头入场，等待新dealing range形成"
    sweep_break_assessment:
      penetration_atr_pct: 52.1
      daily_close_side: opposite
      wick_ratio: 8.3
      ltf_mss_against: false
      ltf_displacement_through: true
      total_score: 5
      classification: break
      classification_confidence: high
```

## 七、Sweep vs. Break 量化判定

当价格触及你标注的 liquidity level 时，使用以下打分体系判断是 sweep 还是 break：

```yaml
sweep_break_scoring:
  # === 指标1：日线收盘位置（权重最高）===
  daily_close:
    same_side:     -2    # 收盘拉回原侧
    at_level:       0    # 收盘恰好在水平附近(±0.1×ATR)
    opposite_side: +2    # 收盘站在另一侧

  # === 指标2：穿透深度 ===
  penetration_vs_atr:
    below_30pct:   -1    # 浅穿透
    30_to_50pct:    0    # 中等
    above_50pct:   +1    # 深穿透

  # === 指标3：影线比例 ===
  wick_ratio:
    above_25pct:   -1    # 长影线（sweep特征）
    10_to_25pct:    0    # 中等
    below_10pct:   +1    # 短影线（break特征）

  # === 指标4：LTF 15分钟结构 ===
  ltf_structure:
    mss_against:   -2    # 出现反方向MSS
    no_structure:   0    # 无明确结构
    displacement:  +2    # 出现同方向displacement

  # === 分类规则 ===
  classification:
    sweep:     "total <= -3"
    ambiguous: "-3 < total < 3"
    break:     "total >= 3"
```

ATR 使用日线 14 周期。Displacement candle 的量化定义是：body 占 range > 70%，range > 1.5 × 最近 20 根 K 线平均 range，收盘在 range 极端 25% 以内。

## 九、每日执行检查清单

将上面所有内容压缩成一个你每天实际操作时可以快速过一遍的流程：

| 时间 (ET)  | 动作                                                         | 产出                            |
| ---------- | ------------------------------------------------------------ | ------------------------------- |
| 8:00       | 打开日线图，确认当前 dealing range 是否仍然 active（昨日收盘是否突破了 swing high 或 swing low） | dealing_range.status            |
| 8:10       | 计算 position_pct，确定价格在 premium 还是 discount          | position_pct, premium_discount  |
| 8:20       | 标注日线 liquidity（上方1-2个，下方1-2个），更新 status（昨天是否已经被 swept/broken） | liquidity.daily                 |
| 8:30       | 切到 4H，在日线 liquidity 附近找 4H 级别的 liquidity 做细化  | liquidity.four_hour             |
| 8:40       | 根据决策矩阵确定 bias、confidence、narrative                 | bias, confidence, narrative     |
| 8:50       | 写 invalidation 条件                                         | invalidation.primary, secondary |
| 9:00       | 填完 YAML，检查一遍                                          | 完整的 htf_context              |
| 9:15       | 停止分析。如果分析没做完，今天 bias = neutral，不做方向性交易 | —                               |
| 9:30       | Bias 锁定。进入执行模式，在 LTF 上按 bias 方向找入场         | —                               |
| 9:30–12:00 | 监控 invalidation。如果触发，写 bias_update，调整操作        | bias_updates, session_events    |
| 收盘后     | 填写 daily_review，更新 liquidity status，做 sweep/break 评估 | daily_review                    |

9:15 的硬截止非常重要。如果你到 9:15 还没确定 bias，说明当天的盘面结构不够清晰，这本身就是一个信号——不清晰就不做。强行在不清晰的日子里找方向是亏损的主要来源之一。

## 十、关于 4H 的定位

最后澄清 4H 在整个体系中的角色，避免混淆。

4H **不用于**判断 dealing range。Dealing range 只看日线。4H **不用于**判断 bias 方向。方向只由日线位置和日线 liquidity 决定。

4H **用于**两件事。第一是在日线 liquidity 附近细化具体的 level，帮你把"2398.5 附近"精确到"2396.0–2398.5 这个区间"。第二是在 bias 确定后，观察 4H 的 order flow 是否支持你的 bias——比如你的 bias 是 bearish，但 4H 持续在打出 higher high 和 higher low，这虽然不直接推翻你的 bias（日线才能推翻），但它提示你今天可能不是做空的好时机，可以选择观望。

这种分层——日线定方向，4H 做确认，15 分钟找入场——让每个时间框架都有明确且不重叠的职责。
